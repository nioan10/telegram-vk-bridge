# Telegram → VK: сообщения с #важно

Отдельный бот для одной пары: **закрытая группа Telegram → беседа VK**.
Он копирует новые сообщения с выбранным хештегом от имени сообщества VK.
Владелец также может написать или переслать сообщение боту в личку: оно уйдёт в ту же беседу без хештега.
Проект автономный: не использует код, сервер, базу, ключи или Docker Compose соседних проектов.

## Что реализовано

- Фильтр по полному хештегу в тексте или подписи. `#важно` и `#ВАЖНО` подходят, `#важное` — нет.
- Смена хештега через личную команду `/tag #срочно`; настройка сохраняется после перезапуска.
- `/tag off` отключает фильтр: из настроенной группы пересылаются все новые сообщения. `/tag #важно` возвращает фильтр. Служебные события группы (вход участников, закрепления) не пересылаются; ограничения вложений сохраняются.
- Ручная отправка владельцем через личку бота без тега. При пересылке сохраняется доступное имя первоначального автора.
- Личная отправка и команды доступны только аккаунту с настроенным `TELEGRAM_OWNER_ID`. Другие пользователи игнорируются.
- Текст, обычные ссылки, ссылки под текстом, фото и фотоальбомы. Если тег есть в одной подписи альбома, переносятся все его фото.
- Стикеры: обычные WEBP/PNG превращаются в изображения PNG, анимированные TGS и видеостикеры WEBM — в GIF-вложения VK. Это не стикеры из магазина VK. Прозрачность заменяется белым фоном, GIF ограничены 320×320, 15 кадрами/с и 3 секундами. У стикера нет подписи с хештегом: в группе нужен `/tag off`, в личке владельца фильтра нет.
- Имя автора в копии; его можно отключить. Хештег можно сохранять или убирать.
- Разделение длинного текста, обработка эмодзи и Telegram-смещений UTF-16.
- SQLite-очередь, восстановление после перезапуска, повторы при сетевых ошибках и ограничениях API.
- Ответы на личные команды тоже хранятся в очереди и повторяются после сетевой ошибки или перезапуска. Если Telegram принял ответ, но соединение оборвалось до подтверждения, возможен повтор ответа; сама команда повторно не применяется.
- Сохранение `random_id` и готового сообщения до отправки в VK, чтобы уменьшить риск дубля при потерянном ответе API.
- Проверка доступов, поиск ID чатов, состояние очереди, ручной повтор после исправления постоянной ошибки.
- Docker Compose для VPS: автоперезапуск, отдельный постоянный том, непривилегированный пользователь, без входящих портов. Лимиты контейнера: 256 МБ памяти, 0.5 CPU и 64 процесса.
- Python 3.10+, зависимости из `requirements.txt` и FFmpeg для видеостикеров. В Docker всё устанавливается автоматически.

**Статус:** автоматические тесты выполняются на Windows и Linux; Docker-образ проверен на VPS. Доставка текста из Telegram-группы в реальную беседу VK подтверждена. Автоматические тесты вложений используют подменённые API; после установки выполните проверку своих чатов по инструкции ниже.

## Что потребуется от владельца

1. Возможность добавить бота в исходную группу Telegram и дать ему видеть сообщения.
2. Новый Telegram-бот через [@BotFather](https://t.me/BotFather) и его токен.
3. Сообщество VK, которым вы управляете, и ключ сообщества с доступом к сообщениям, фотографиям и документам (документы нужны для GIF-стикеров).
4. Возможность добавить это сообщество в целевую беседу VK и разрешить отправку сообщений.
5. Linux VPS с Docker Engine и Compose v2. Для небольшой группы ориентир — 1 vCPU и 512 МБ–1 ГБ RAM; фактическая потребность зависит от вложений. Нужен исходящий HTTPS к Telegram и VK. Домен и открытие новых входящих портов боту не нужны.

Токены впишите непосредственно в `.env` на своей машине или VPS. Не отправляйте их в переписку, не помещайте в команды оболочки, коммиты или скриншоты. Для помощи с развёртыванием достаточно адреса VPS, имени SSH-пользователя и уже настроенного доступа; приватный SSH-ключ пересылать не нужно.

## 1. Telegram

1. В BotFather выполните `/newbot`, задайте имя и username. Создайте отдельного бота для этой связки.
2. Добавьте его в закрытый чат.
3. Выберите один способ дать ему читать сообщения:
   - назначьте бота администратором, отключив ненужные права управления;
   - либо в BotFather: `/setprivacy` → ваш бот → `Disable`, после чего удалите бота из группы и добавьте заново.
4. Сохраните токен из BotFather для `.env`.

Участникам группы не требуется отдельно нажимать `/start` в личке бота. Владелец открывает личку для ручной отправки и управления фильтром. Если в группе включена защита от пересылки, проверка остановит запуск; изменение этого режима согласуйте с владельцем группы.

## 2. VK

1. Создайте отдельное сообщество для бота или используйте своё существующее.
2. В управлении сообществом включите **Сообщения** и **Возможности ботов**. Разрешите добавлять сообщество в беседы.
3. Через действие сообщества «Добавить в беседу» / «Добавить в чат» добавьте его в нужную беседу. Названия элементов интерфейса могут отличаться.
4. В разделе работы с API / ключами доступа создайте **ключ сообщества** с разрешениями на сообщения, фотографии и документы. Используется ключ сообщества, не личный токен пользователя.
5. В беседе отправьте сообщение с упоминанием сообщества. Убедитесь, что сообществу разрешено писать. Если оно не видит беседу, администратор должен проверить права бота; в отдельных настройках потребуется роль администратора беседы.

Входящий VK Long Poll и Callback API этой программе не нужны: она только отправляет в VK. Участники увидят сообщения от имени сообщества.

## 3. Разместить на VPS

Скопируйте **только эту папку**, например в `/opt/telegram-vk-bridge`, либо клонируйте её отдельный репозиторий. Следующие команды выполняются внутри папки проекта. Docker/Compose должны быть уже установлены по [официальной инструкции Docker](https://docs.docker.com/engine/install/).

```sh
cd /opt/telegram-vk-bridge
cp .env.example .env
chmod 600 .env
nano .env
```

Пока заполните только `TELEGRAM_BOT_TOKEN` и `VK_ACCESS_TOKEN`. Значения вводятся без пробелов и без комментариев в конце строки. `HASHTAG=#важно` оставьте как есть. Не меняйте `DATA_DIR` для обычного Docker-запуска.

Если на сервере установлен Python 3.10+, вместо копирования и ввода токенов в редактор можно выполнить `python3 -m bridge init`: он запросит оба ключа скрыто и создаст `.env` с правами `600`. Существующий файл команда не перезаписывает.

Соберите образ:

```sh
docker compose build
```

Определите Telegram ID:

```sh
docker compose run --rm bridge discover-telegram
```

Пока команда ожидает, отправьте в исходную группу `/bridge_id@имя_вашего_бота`.
Скопируйте выведенное `TELEGRAM_CHAT_ID=-...` в `.env`.
Команда работает с новыми событиями Bot API, а не читает всю историю группы.

Определите **свой** ID для личной отправки и настройки фильтра:

```sh
docker compose run --rm bridge discover-owner
```

Отправьте `/bridge_id@имя_вашего_бота` **в личку боту со своего аккаунта**.
Проверьте имя аккаунта в выводе и впишите полученное `TELEGRAM_OWNER_ID=...` в `.env`.
Это числовой ID, не `@username`. Используйте команды discovery до запуска основного контейнера.

Определите VK ID:

```sh
docker compose run --rm bridge discover-vk
```

Выберите **нужную беседу по названию** и впишите её `VK_PEER_ID=200000000...` в `.env`.
Значение берите из команды: ID той же беседы в личном аккаунте может отличаться от ID, видимого сообществу.
VK может возвращать пустой список даже для беседы, в которую сообщество уже добавлено. Повторные упоминания не гарантируют её появления. В этом случае требуется ID беседы, полученный именно в контексте сообщества (например, из события VK API), и проверка через `check`. Автоматическое обнаружение через события пока не реализовано; ID из личного аккаунта не подставляйте наугад.

Текущая проверка запуска запрашивает объект беседы через `messages.getConversationsById`. В проверенном сценарии VK открыл этот объект только после назначения сообщества администратором беседы, хотя отправка сообщений была разрешена и до этого. Если `check` не видит известную беседу, проверьте роль сообщества; после изменения роли повторите `check`. Код бота не использует функции модерации.

Проверьте итоговый маршрут:

```sh
docker compose run --rm bridge check
```

Команда проверит Telegram-бота, доступ к группе, режим приватности, выбранную VK-беседу и получение адреса загрузки фото. Она ничего не отправляет в чаты. Проверьте названия обоих чатов в выводе.

Запустите:

```sh
docker compose up -d
docker compose logs --tail=50 -f bridge
```

Выход из просмотра логов: `Ctrl+C`. Бот продолжает работать. В логах не выводятся токены, текст сообщений или имена их авторов; остаются ID заданий и коды ошибок.

После изменения `.env` примените настройки командой `docker compose up -d --force-recreate`. Простой `restart` не перечитывает `env_file` контейнера.

## 4. Проверить в своих чатах

После строки «Бот запущен»:

1. Напишите в Telegram `#важно Проверка связи`. В VK должна появиться одна копия с именем автора.
2. Напишите сообщение без тега — копии быть не должно.
3. Отправьте фото с подписью `#важно Фото`.
4. Отправьте альбом с тегом в одной подписи. Дождитесь нескольких секунд: фото должны прийти вместе.
5. Выполните `docker compose restart`, затем отправьте ещё одно отмеченное сообщение. Старые уже подтверждённые сообщения не должны повторяться.
6. Напишите или перешлите боту сообщение в личку без тега: оно должно прийти в VK, а бот ответит «Отправлено в VK».
7. В личке отправьте `/tag #срочно`. Теперь проверьте, что из общего чата проходит `#срочно`, а прежний тег — нет. `/tag #важно` вернёт исходный фильтр.
8. После перезапуска отправьте `/tag`: выбранный фильтр должен сохраниться.

Именно эта проверка подтверждает работу с вашими реальными разрешениями и сетью VPS. Автоматические тесты её не заменяют.

## Управление в личке Telegram-бота

| Действие | Результат |
| --- | --- |
| Написать обычное сообщение | Отправка в VK без хештега |
| Переслать сообщение, фото, альбом или стикер | Отправка поддерживаемого содержимого в VK без хештега |
| `/tag` | Показать текущий режим пересылки общего чата |
| `/tag off` | Отключить фильтр и пересылать все новые сообщения общего чата |
| `/tag #объявление` | Сохранить новый хештег для следующих сообщений общего чата |
| `/status` | Показать фильтр, количество ожидающих, ошибочных и доставленных заданий |
| `/bridge_id` | Показать свой Telegram ID |
| `/start` или `/help` | Показать подсказку |

Команды принимаются только **в личке от владельца**. Они не отправляются в VK. Сообщения лички, начинающиеся с `/`, считаются командами; для отправки такого текста добавьте обычный текст перед слешем.
В режиме фильтра хештег один; регистр не важен. `/tag off` отключает фильтр, а `/tag #важно` включает его снова. Настройка меняет обработку следующих событий, уже принятые в очередь задания не отменяет. Если команда и сообщения группы пришли в одной порции событий, они обрабатываются по порядку. Старую историю бот не импортирует.

Подтверждение личной отправки приходит после успешного ответа VK. Если ответ Telegram не дошёл, это не вызывает повторную отправку в VK. При задержке смотрите `/status`. Если часть вложений не поддерживается, бот укажет это в подтверждении и копии.

## Настройки

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Секретный токен отдельного Telegram-бота |
| `VK_ACCESS_TOKEN` | Секретный ключ сообщества VK |
| `TELEGRAM_CHAT_ID` | Единственная исходная группа, отрицательное число |
| `VK_PEER_ID` | Единственная целевая беседа, ID из `discover-vk` |
| `TELEGRAM_OWNER_ID` | Числовой ID владельца из `discover-owner`; доступ к личной отправке и командам |
| `PRIVATE_INBOX_ENABLED` | `true` включает личную отправку и управление; по умолчанию `true` |
| `HASHTAG` | Начальный хештег при создании базы; по умолчанию `#важно`, `off` отключает фильтр. Затем управляйте через `/tag` |
| `STRIP_HASHTAG` | `true` убирает выбранный тег из копии; по умолчанию `false` |
| `INCLUDE_AUTHOR` | `true` добавляет имя автора; по умолчанию `true` |
| `ALBUM_WAIT_SECONDS` | Ожидание частей альбома после последней полученной части; по умолчанию 5, от 2 до 60 |
| `DATA_DIR` | Каталог SQLite и блокировки; в Docker оставьте `state` |
| `VK_API_VERSION` | Версия API; по умолчанию `5.199` |

Переменные окружения имеют приоритет над `.env`. Чтение `.env` буквальное: переменные и команды внутри значений не исполняются. Для другого файла: `python -m bridge --env-file /путь/к/.env check`.
Выбранный через бота хештег хранится в SQLite и имеет приоритет над начальным `HASHTAG` из `.env`. Если личный режим отключён, команды в личке также отключаются. Для текущего сценария оставьте `PRIVATE_INBOX_ENABLED=true`.

## Обслуживание

```sh
# Очередь и последние постоянные ошибки
docker compose exec bridge python -m bridge status

# Состояние контейнера / healthcheck
docker compose ps

# Остановить отправку, сохранив очередь
docker compose stop

# После исправления прав вернуть failed-задания в очередь
docker compose run --rm bridge retry-failed
docker compose up -d
```

Сетевые ошибки, ограничения частоты и временные сбои API повторяются автоматически с паузой.
Ошибки прав, неверные параметры и неподдерживаемый размер фото сохраняются как `failed`: исправьте причину, остановите бот и выполните `retry-failed`. Ошибка одного задания не удаляет остальные.
HTTP 401/403 и VK 5/15 обычно требуют проверки ключа и прав; Telegram HTTP 409 — проверки, что другой процесс не использует того же бота. Подробные расшифровки проверяйте по официальной документации API.

Состояние находится в Docker-томе `bridge-state` этого Compose-проекта. **Не удаляйте том через `docker compose down -v`**: он содержит ожидающие сообщения, позицию чтения и информацию о доставке. Для резервной копии сначала остановите контейнер и сохраните том средствами вашей инфраструктуры. Незавершённая очередь содержит приватный текст и ссылки на файлы; её резервная копия также должна оставаться закрытой.

База привязана к исходной группе, целевой беседе, Telegram bot ID, ID владельца и отпечатку ключа VK. Это предотвращает отправку старой очереди в другую беседу при ошибочной смене настроек. При смене пары чатов, владельца или ключа VK запустите отдельный экземпляр с **новым** томом состояния после обработки старой очереди. Если ключ пришлось срочно отозвать, старая очередь сохранится, но автоматический перенос её в новый экземпляр не реализован.

Один экземпляр на пару чатов. Локальная блокировка не позволяет двум процессам работать с одной базой. Не запускайте одного Telegram-бота одновременно на разных серверах: общую очередь Telegram они будут делить.

## Границы первой версии

- Направление только Telegram → VK: одна группа по хештегу плюс личная отправка владельца, одна целевая беседа. Другие пользователи и группы игнорируются.
- На первом запуске берутся сообщения, созданные с момента старта `run`. Старые сообщения и прежняя история не импортируются. При перезапуске позиция чтения сохраняется.
- Telegram хранит неполученные обновления ограниченное время (до 24 часов). Отключение VPS дольше этого срока может привести к пропуску сообщений, которые ещё не попали в локальную очередь.
- Правки, удаление сообщений, реакции, ответы/ветки и добавление тега через редактирование не синхронизируются. Для отправки после правки создайте новое сообщение с тегом.
- Обычные видео, голосовые, документы, опросы и прочие вложения не переносятся. Если сообщение выбрано фильтром, передаётся текст с пометкой о пропущенном типе вложения. Видеостикеры поддерживаются отдельно от обычных видео.
- Входной стикер ограничен 4 МБ, распакованный TGS — 2 МБ, результат — 8 МБ. Конвертация идёт в отдельном процессе без токенов в окружении и с таймаутом 45 секунд. Повреждённое или слишком сложное вложение остаётся в `failed`, остальные задания продолжают обрабатываться.
- Фото, отправленное «как файл», считается документом. Для переноса отправляйте обычное фото. Фото больше 20 МБ не обрезаются и не теряются молча: задание остаётся в `failed`.
- Альбом собирается по паузе между частями. Необычно поздняя часть, пришедшая после закрытия альбома, пропускается с записью в лог; при необходимости увеличьте `ALBUM_WAIT_SECONDS`.
- Текстовое форматирование Telegram не воспроизводится; скрытые ссылки раскрываются рядом с подписью. Упоминания и предпросмотр ссылок в VK отключены.
- Сохраняются ID доставленных заданий и стабильный `random_id` при повторе. Абсолютная гарантия «ровно один раз» зависит также от поведения и срока дедупликации VK; при удалении базы или запуске с новым томом эта защита не переносится.
- После завершения задания текст и данные фото убираются из рабочих таблиц. Это не является гарантией криминалистического стирания из файлов SQLite, журналов или резервных копий.

## Запуск без Docker

В Windows используйте `python`, в Linux обычно `python3`. Установите Python-зависимости; для WEBM-стикеров также нужен `ffmpeg` в PATH (в Debian/Ubuntu: `sudo apt-get install ffmpeg`).

```sh
python -m pip install -r requirements.txt
python -m bridge init
python -m bridge discover-telegram
python -m bridge discover-owner
python -m bridge discover-vk
# Впишите ID в .env
python -m bridge check
python -m bridge run
```

Процесс должен оставаться запущенным. Для VPS предпочтителен Compose с постоянным томом и автоперезапуском.

## Тесты и Git

```sh
python -m unittest discover -s tests -v
```

Проверяются изоляция исходного чата, точное совпадение тегов, UTF-16, альбомы, транзакционность очереди и позиции чтения, перезапуск, повтор после неопределённого результата отправки, продолжение длинных сообщений, ошибки API, блокировка второго процесса и отсутствие ключей в сообщениях об ошибках.

Репозиторий: [nioan10/telegram-vk-bridge](https://github.com/nioan10/telegram-vk-bridge). В нём есть `.gitignore`, `.gitattributes` и GitHub Actions для тестов и сборки Docker. Для установки на свой сервер:

```sh
git clone https://github.com/nioan10/telegram-vk-bridge.git
cd telegram-vk-bridge
```

При публикации изменений убедитесь, что `.env`, `state/`, базы, архивы и локальные файлы агентов отсутствуют в списке подготовленных файлов.

## Использованные API

- [Telegram Bot API](https://core.telegram.org/bots/api): `getMe`, `getWebhookInfo`, `getChat`, `getChatMember`, `getUpdates`, `getFile`, `sendMessage`.
- [Какие сообщения видит Telegram-бот](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get).
- [Официальная схема методов сообщений VK](https://github.com/VKCOM/vk-api-schema/blob/master/messages/methods.json): просмотр бесед и `messages.send`.
- [Официальная схема фото VK](https://github.com/VKCOM/vk-api-schema/blob/master/photos/methods.json): `photos.getMessagesUploadServer`, `photos.saveMessagesPhoto`.
